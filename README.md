## 🔬 Research Hypothesis

The work is centered on a **single, structural (topological) hypothesis** — formulated with no ideological party labels — validated statistically against a null model.

| Hypothesis | Statement | Verdict |
|-----------|-----------|---------|
| **H1** | The co-authorship network has a **non-random community structure**: observed modularity *Q* is significantly higher than that of degree-preserving weighted null graphs | ✅ Confirmed (4/4 years, *p* < 0.005) |

**How it is tested.** For each year, the observed Louvain modularity *Q*ₒᵦₛ is compared against a null distribution of 200 randomised graphs generated by `double_edge_swap` (which preserves the exact degree sequence). Because the swap drops edge weights, the original weight multiset is reassigned to the rewired edges, so the null stays **weighted and like-for-like** with *Q*ₒᵦₛ. The *p*-value uses the add-one estimator *p* = (*r*+1)/(*m*+1) (North et al., 2002), so it is never exactly zero: with 0 null graphs reaching *Q*ₒᵦₛ out of 200, *p* = 1/201 ≈ 0.005.

> **H1 is a condition of validity, not the headline finding.** Before interpreting centralities and communities as influence structures, one must show the modular organization is not an artifact of chance or the degree sequence. The observed *Q* strictly exceeds **every** null graph in all four years.

> **Descriptive deliverables.** Beyond H1, the architecture also produces node centralities (degree, betweenness, closeness, eigenvector) and a second community partition via Label Propagation. These are **not** hypotheses — they are the analytical output of the network-analysis architecture. Agreement between the Louvain and Label Propagation partitions is quantified with the Adjusted Rand Index (ARI), serving as a robustness cross-check for H1.

## 🏗️ Architecture

Pipeline with single-responsibility layers, following Clean Architecture + SOLID. The **Dependency Rule** is strict and non-negotiable — it is part of the thesis defense:

```
extraction → processing → core (Graph + Algorithms) → repository → visualization
```

- `models/` imports only the standard library (pure dataclasses — no external validation lib, by design).
- `core/` never knows that JSON, SQLite, CSV, or HTTP exist — all serialization lives in `repository/`.
- External-format parsing lives exclusively in `extraction/` and `processing/`.

| Layer | Responsibility |
|-------|----------------|
| **extraction/** | Download and local cache of CSVs from the Chamber's open-data portal (via `pandas`) |
| **processing/** | Cleaning, filtering (by proposition type + `max_authors`), party/state sanitization, conversion to domain objects |
| **core/graph.py** | Bipartite projection → weighted co-authorship graph; centralities; community assignment |
| **core/algorithms/** | Centrality metrics, community detection (Louvain, Label Propagation), null-model validation (H1), aggregate typed result + ARI |
| **models/** | Domain entities (Deputy, Proposition, CoauthorshipEdge, ParliamentaryNetwork) |
| **repository/** | Export to CSV, GEXF (Gephi), SQLite, and `AnalysisResult` ↔ JSON |
| **visualization/** | Automated per-year plots |
| **scripts/** | Cross-year comparative analysis and data-maintenance utilities |
| **tests/** | 210 tests, 83% overall coverage (core ≥ 93%) |

## 🧮 Mathematical Model

**Bipartite projection** — the network of deputies (*D*) and propositions (*P*) is projected onto deputies only, producing a weighted graph where an edge means "co-authored at least one proposition".

**Edge weight** — normalized by group size to penalize mass co-signatures:
```
w(i,j) = Σ  1 / (n_p − 1)    for each shared proposition p (n_p = number of authors of p)
```

**`max_authors` filter** — proposals with more than 30 deputy co-authors are excluded from edge construction. A PEC with 226 signatories generates ~25,400 pairs, pushing density to ~85% and making community detection meaningless. This filter is **active** in every run; a sensitivity analysis of the threshold is registered as future work.

**Uniform type weights (= 1)** — all valid proposition types receive weight 1. No theoretically justified numeric scale exists for weighting PL vs. PEC; qualitative filtering (by type) already performs the relevant selection.

**Centrality representation** — each metric uses the representation coherent with its semantics:
- **Degree (strength)** and **eigenvector** are computed on the **weighted** graph (collaboration intensity accumulates additively).
- **Betweenness** and **closeness** are computed on the **unweighted topology**: NetworkX treats a provided weight as a *distance*, whereas here the weight encodes tie *strength* (the inverse meaning), so using it directly would treat strong ties as far apart.

**Null-model validation (H1)** — 200 randomised graphs via `double_edge_swap` (preserves the degree sequence) with the original edge-weight multiset reassigned (weighted, like-for-like). *p*-value = (*r*+1)/(*m*+1). Randomness is seeded (`seed=42`) for full reproducibility.

**Partition agreement** — Adjusted Rand Index (ARI) between the Louvain and Label Propagation partitions, in [−1, 1]; 0 is chance-level agreement, 1 is identical partitions.

## 🚀 Usage

### Prerequisites

- Docker + Docker Compose (recommended — the canonical environment is Python 3.11)
- Or: Python 3.11+ locally
- Copy `.env.example` to `.env` before running: `cp .env.example .env`

### Docker (Recommended)

```bash
docker compose build                     # Build image
docker compose up pipeline_chamber       # Full multi-year pipeline (2022–2025), ~15–25 min
docker compose run --rm compare          # Cross-year comparison (after the pipeline)
docker compose run --rm tests            # Test suite
```

An `run.sh` helper wraps these: `./run.sh setup | pipeline | compare | test | all | status`.

### Local (without Docker)

```bash
python -m venv venv
source venv/bin/activate        # Linux/Mac  (venv\Scripts\activate on Windows)
pip install -r requirements.txt
cp .env.example .env

python src/main.py              # Run pipeline
python scripts/compare_years.py # Cross-year comparison
pytest src/tests/ -v --cov=src  # Tests with coverage
```

## 🔄 Pipeline Stages

1. **Extraction** — Download/cache CSVs from `dadosabertos.camara.leg.br`
2. **Processing** — Clean data; filter to valid proposition types (PL, PLP, PEC, PDL, EMC); apply the `max_authors=30` filter; sanitize party/state codes
3. **Graph construction** — Bipartite projection *B*=(*D*∪*P*, *E*) → weighted co-authorship graph *G*=(*D*, *E′*, *w*)
4. **Metrics** — Degree, betweenness, closeness, and eigenvector centrality for every deputy
5. **Analysis** — Louvain + Label Propagation (ARI agreement); null-model permutation test (H1)
6. **Repository** — Export to CSV, GEXF, SQLite, and `analysis_{year}.json`
7. **Visualization** — Generate plots to `data/plots/{year}/`

The pipeline runs each year independently (2022–2025). A failure in one year does not stop the others.
